# Test-free stopping under grokking: project plan

**Goal.** Build a *causal* stopping rule that uses no test data and is not fooled by
grokking plateaus. Causal means the decision at step `t` uses only data recorded at or
before `t`. Test accuracy is used only to score the rule.

**Success metric.** The main score is **regret**: `max_t test_acc(t) − test_acc(τ)`,
where `τ` is the step at which the rule stops. Pass/fail within ε, stopping lag and
premature-stop rate are all computed afterwards from the same stored data.

The code structure, classes and data flow are in [DESIGN.md](DESIGN.md). This file
covers *what* we run and *in what order*. A new contributor should start with
[RAMPUP.md](RAMPUP.md).

**Status (2026-10-22):** Phases 0 and 1 are done (including the Phase 1b clean-up run).
Phase 2a ran (results: [results/phase2/RESULTS.md](results/phase2/RESULTS.md)); the Phase 2b
notebook is written and waiting to run.
**Phase 2 (the pilot sweep) is next.** Phase 1 findings are in
[results/phase1/RESULTS.md](results/phase1/RESULTS.md) and summarized in §9.

## 1. Fixed decisions

| Topic | Decision |
|---|---|
| Architecture | Plain fully connected MLP with biases. No normalization layers. Depth, width and activation are chosen per application. |
| Applications | Modular arithmetic, MNIST subset, teacher–student regression |
| Loss | Fixed per application: cross-entropy for modular, MSE for MNIST and teacher–student |
| Optimizers | AdamW (decoupled weight decay), Adam + L2 (coupled), SGD + momentum 0.9 + L2, plain SGD + L2 |
| Information a metric may use | Training data, weights, recorded training telemetry, hyperparameters (γ, lr, …). **Never test data.** |
| Metric computation | Entirely **offline** from stored run data plus deterministic replay, with causality enforced in code |
| Calibration split | Held-out seeds within each application: seeds {0, 1} calibrate, {2, 3} are held out |

| Where runs execute | **The corpus is trained and replayed on the Molab GPU only.** CPU is for development and tests. CPU numerics are pinned so they are reproducible too (§4.1), but the corpus never depends on CPU. |
| Storage location | Molab files do not persist. Each finished run goes to a **public Hugging Face dataset repo** under the account `advay333`. |
| Compute | Molab: NVIDIA RTX PRO 6000 Blackwell (96 GB), 20 CPUs, 12-hour sessions. Local: RTX 4060 (8 GB); the local dev venv is CPU-only torch. |
| Code | Written from scratch in this directory. Nothing is imported from `agop_alignment_testing/`. |

## 4. What each run records

Everything a metric could need is stored, so new metrics never require retraining.
Details are in DESIGN.md §5.

| Stream | Cadence | Contents | Visible to metrics? |
|---|---|---|---|
| **Telemetry** | every `log_every` steps (default 50) | Train loss and accuracy. Per-layer weight norm, gradient norm (data term and regularizer term separately), update norm. The radial and tangential parts of each update. The cosine between gradient and weights. | yes |
| **Train predictions** | every `log_every` steps | argmax predictions on the training set (int16). Teacher–student stores the per-sample RMS error instead (float16). | yes |
| **Dense summaries** | every `summary_every` steps (default 500) | Per-layer singular values of W. Training-set activation-covariance spectra per hidden layer. Gradient-noise statistics on 8 fixed probe minibatches. **float32, O(width) numbers per layer.** Full matrices such as WᵀW come from replay. | yes |
| **Weight fingerprints** | every `log_every` steps | Per parameter tensor: sum, sum of squares, and projections onto 8 fixed random vectors. Lets replay be checked at **any** log step, not just at keyframes. | no: replay verification only |
| **Keyframes** | every `keyframe_every` steps (default 10k; about 11 per run including step 0 and the final step) | **Complete training state**: weights and optimizer state (Adam moments, momentum buffers). No RNG state is needed: minibatch order is a pure function of the step. Stored in fp32. | via replay only |
| **Oracle** | every `log_every` steps | Test loss and accuracy | **no**: scoring only |
| **Metadata** | once | Full config, seeds, code git hash, package versions, torch/CUDA/cuDNN versions, GPU and CPU model, determinism flags, wall time, status | config only |

Anything not in the dense streams is obtained by **replay**. To get the weights at step t:
restore the last keyframe at or before t, then run the identical training loop forward
to t. Replay only ever uses the past, so it does not weaken causality.

Per-example gradients, minibatch gradient disparity, activation statistics, WᵀW and
AGOPs at arbitrary steps are computed during replay. One replay pass per run feeds
**all** signals that need weights, so the extra cost is about one training run per run,
at any time resolution we choose.

### 4.1 Deterministic reproducibility (hard requirement)

Every run must be reproducible from its config, seed and code version. Replay is only
trusted if it reproduces the recorded run.

**Determinism setup** (fixed in code, recorded in metadata):
- `torch.use_deterministic_algorithms(True)`, `CUBLAS_WORKSPACE_CONFIG=:4096:8`,
  cuDNN benchmark off, TF32 off for matmul and cuDNN.
- **CPU numerics pinned** (`tfs/cpu_env.py`): `MKL_DYNAMIC=FALSE`, `OMP_DYNAMIC=FALSE`,
  `MKL_CBWR=AUTO,STRICT`, oneDNN off. Every worker, CPU or GPU, gets an equal share of the
  CPUs actually available. Phase 1 found load-dependent CPU drift without this (§9).
- All randomness drawn from named seed streams (data, teacher, init, order, probe,
  fingerprint). Minibatch order is a pure function of (seed, step).
- Replay runs on the **same GPU model and the same software stack** as the original run.
  Metadata records these, and replay refuses a mismatched environment unless overridden.

**Verification levels:**

| Level | Check | Pass condition |
|---|---|---|
| **L0: exact** (target) | SHA-256 of every tensor in the keyframe reached by replay vs. the stored keyframe; telemetry, fingerprints and predictions replayed vs. stored | Bit-identical |
| **L1: tolerance** (minimum acceptable) | Per tensor, at every keyframe: ‖w_replay − w_stored‖ / ‖w_stored‖. At every log step: fingerprints and telemetry, relative difference. Train predictions. | weights ≤ 1e-6 relative; optimizer state ≤ 1e-5; fingerprints and telemetry ≤ 1e-5; train-prediction agreement ≥ 99.9% |
| **L2: decision** (sanity, Phase 4) | Every stopping rule's τ computed from replayed signals vs. from dense recorded signals, on the debug set | identical τ |

- Every run carries a `replay_level` (in `replay_report.json` and the manifest): `L0`,
  `L1` or `failed`. **Runs that are `failed` are excluded from the corpus** and rerun.
- **Phase 1 result:** every GPU check was L0 with zero error (32 configs over two runs,
  20k steps each). No drift was observed, so the L1 tolerances in
  `configs/replay_tolerance.yaml` stay at their starting values. They are a safety net,
  not a measured operating point.

## 5. Metrics to evaluate

Each metric produces a **signal**: a time series computed causally from stored data. A
shared **rule template** turns a signal into a stopping step: causal smoothing, then a
threshold (with direction), then a patience window. The rule's hyperparameters are
calibrated on seeds {0, 1} and scored on seeds {2, 3}.

### Candidates

| ID | Family | Signal |
|---|---|---|
| S1 | Regularized-objective stationarity | ‖∇L_data + γw‖ / ‖γw‖ (coupled optimizers). For AdamW, ‖Δw‖ / (lr·γ·‖w‖). Also the rate of change of log‖w‖ relative to −lr·γ. All per layer and aggregated. |
| S1b | Same family | Mahsereci's evidence-based criterion with the weight-decay term added (gradient SNR computed from per-example gradients) |
| S1c | Same family | S1 with the logit-scaling direction projected out, to survive softmax collapse (cross-entropy runs) |
| N1 | Weight norm | ‖w‖ per layer and its log-derivative |
| R1 | Rank / spectrum | Effective rank, participation ratio and spectral entropy of each layer's activation covariance on the training set |
| R2 | Same family | The same three spectral measures on each weight matrix |
| F1 | Feature stationarity | ‖ΔNFM_l‖ / ‖NFM_l‖ between consecutive evaluation steps, where NFM_l = W_lᵀW_l (from replay) |
| F2 | Same family | Increment and consecutive alignment of the input AGOP, (1/n)Σ JJᵀ |
| F3 | Same family | Linear CKA between consecutive training-set feature snapshots, per layer |

### Baselines

| ID | Baseline | Note |
|---|---|---|
| B0 | Fixed budget | Stop at step T_fixed |
| B1 | Training-loss patience | Expected to stop on the plateau |
| B2 | Mahsereci et al. 2017 evidence-based criterion | No weight-decay term. Expected to stop on the plateau. |
| B3 | Gradient disparity (Forouzesh & Thiran 2021) | |
| B4 | Label Wave (Yuan et al. 2024) | Expected to stop on the plateau |
| B5 | HTSR α and correlation traps (Prakash & Martin 2025/26) | Main competitor |
| B6 | Validation-loss patience | **Oracle reference**: uses held-out data, so it is reported separately and never counted as a contender |

### Scoring

Computed per run, then aggregated per application and overall.

- **Regret** (main score): `max_acc − acc(τ)`
- **ε-pass**: `acc(τ) ≥ max_acc − ε`, with ε = 0.01
- **Lag**: `τ − t_ε`, where `t_ε` is the first step with `acc ≥ max_acc − ε`
- **Premature-stop rate**: fraction of runs with `τ < t_ε`
- **Never-stopped rate**: fraction of runs with no stop inside the horizon
- **Seed variance**: of each of the above

### Phase 3: full sweep (Molab)
- Launch in batches by application. Each run uploads to Hugging Face when it finishes.
  A manifest tracks status, so an interrupted session resumes by skipping completed runs.
- **G3:** The manifest shows every run `complete`. A random 5% of runs are
  re-downloaded, pass integrity checks, and are **fully replayed** end to end at L0 or L1.
  Every other run gets a cheap replay check: one randomly chosen keyframe interval.
  Any run at `failed` is retrained. The corpus summary is generated: max accuracy per
  run, t_ε, and a category for each run (§3 categories).

### Phase 4: signals
- Implement every signal (S, N, R, F, B families) against the causal stream API. Signals
  that need weights at arbitrary steps get them from the replay-backed stream: one replay
  pass per run feeds all such signals together. During that pass, replay is checked
  against the stored fingerprints at every log step, and the pass aborts on any
  out-of-tolerance step.
- **Causality test (required for every signal):** Perturb all stored data after step t.
  The signal values at steps ≤ t must not change.
- Compute signals for the whole corpus. Cache them as Parquet, one file per
  (signal, run). Upload the cache to HF as well.
- **G4:** All causality tests pass. The signal cache is complete. Diagnostic plots exist
  for each signal on a fixed debug set of runs.

### Phase 5: rules, calibration, evaluation
- Grid-search each rule's hyperparameters on seeds {0, 1}, minimizing mean regret. Ties
  are broken by lag.
- Calibrate two ways: per application, and one global setting across all applications.
  The second tests whether a rule transfers.
- Score on seeds {2, 3}. Produce the results tables and plots.
- **G5:** A reproducible `evaluate` command regenerates every table from the HF data
  from scratch.

### Phase 6: analysis and write-up
- Failure analysis by run category: which rules stop on the plateau, which stop late on
  the late-collapse runs, which are fooled by slingshot or softmax collapse.
- Ablations: per-layer vs. aggregated signals; smoothing; dependence on evaluation
  resolution (cheap to vary, since replay gives any step).

## 7. Compute plan

**Measured in Phase 1/1b:**
- Throughput collapsed as GPU workers increased: 488 steps/s at 8 workers, 109 at 16, 24
  at 32 (MPS at 16: 125). GPU utilization had a median of 19%. The cause was CPU
  oversubscription: GPU workers had no thread share, so each started one thread per
  core on a 20-CPU machine. On top of that, the batch order was rebuilt on the CPU
  every step. **Both are fixed but not yet re-measured.**
- In the busier Phase 1 run (10–16 concurrent processes, before the fix), 1e5-step runs
  took about 7 min (teacher–student), 8 min (modular), 9 min (MNIST depth 3) and 15 min
  (MNIST depth 8).
- Results were bit-identical at every concurrency level and under MPS.

**Measured in Phase 2a (after the fix):** 819 / 1212 / 1329 / 1378 aggregate steps/s at
4 / 8 / 12 / 16 time-sliced workers (GPU 98% busy), and **2547 under MPS at 16 workers**,
bit-identical everywhere. The corpus therefore runs under MPS; Phase 2b measures 16 / 24 /
32 MPS workers.

**Projection (to be replaced by Phase 2 block 5):** about 1,660 runs at 1e5 steps is
1.7e8 optimizer steps. At ~2,000 aggregate steps/s that is ~23 h of training. Plus one
replay pass per run in Phase 4 (about the same again, plus signal math), that is 2–4
twelve-hour Molab sessions for each of Phases 3 and 4. If the re-measured throughput
is poor, the next lever is training several runs in one process (`torch.func`
batching); this needs determinism re-verified.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Molab session ends mid-batch | Runs are short. The manifest plus per-run upload means we lose at most the runs in flight. |
| Notebook output does not render after a long cell (happened in Phase 1b) | Every notebook prints each table to the console as it is produced and uploads a `summary.md` with the JSON reports. Results are read back from HF (public repos). |
| Hugging Face commit rate limits / file counts | Upload in batched commits (about 10 runs per commit), about 9 files per run, ~15k files in total. |
| Replay is not reproducible (GPU nondeterminism, library or driver updates) | Determinism flags in code; environment recorded per run; L0/L1 verification on every replay; hard gates. The keyframe interval bounds how far drift can spread. |
| Molab's environment changes between sessions | Pin versions (`configs/env_lock.txt`, Phase 2). Record the driver, CUDA, GPU and CPU model per run. Replay refuses a mismatched environment unless explicitly overridden, and even then it must still pass L1. |
| CPU drift returns | The corpus never runs on CPU. The CPU fix passed one 16-config check under load; with a 1–2/16 base failure rate that is evidence, not proof. |
| Some combinations never grok within the horizon | Expected. They form the never-generalizes category, and the pilot ensures there are enough grokkers too. |
| Softmax collapse / NaNs in cross-entropy runs; SGD divergence | Recorded as a run outcome (`status=diverged`), not a failure. Detection happens at the next log step (up to `log_every` steps late, to avoid a per-step GPU sync). Diverged runs are scored separately. |

- **Phase 1 closed (2026-10-21), after the Phase 1b clean-up run.** Full results:
  [results/phase1/RESULTS.md](results/phase1/RESULTS.md).
  - GPU determinism L0 everywhere.
  - **CPU drift** reproduced unpinned (1/16 configs; 2/16 in Phase 1) and gone when
    pinned (16/16). Dynamic threading or oneDNN; which one was not isolated.
  - **Teacher–student accuracy** is RMS error < θ. The Phase 1 version used MSE < θ,
    which was about 100× too loose in squared terms: a model that had not generalized
    scored ~88% test accuracy.

    which projected to ~1 TB for the corpus.

  - **Teacher–student γ = 0.03 at α = 2** is still rising at 1e5.

    fixed, re-measured in Phase 2.
  - **MNIST α = 1 control** shows a late test collapse, which is a valuable trap case.
