# Test-free stopping under grokking: project plan

**Goal.** Build a *causal* stopping rule that uses no test data and is not fooled by
grokking plateaus. Causal means the decision at step `t` uses only data recorded at or
before `t`. Test accuracy is used only to score the rule.

**Success metric.** The main score is **regret**: `max_t test_acc(t) − test_acc(τ)`,
where `τ` is the step at which the rule stops. Pass/fail within ε, stopping lag and
premature-stop rate are all computed afterwards from the same stored data.

The code structure, classes and data flow are in [DESIGN.md](DESIGN.md). This file
covers *what* we run and *in what order*.

---

## 1. Fixed decisions

| Topic | Decision |
|---|---|
| Architecture | Plain fully connected MLP. No normalization layers. Depth, width and activation are chosen per application. |
| Applications | Modular arithmetic, MNIST subset, teacher–student regression |
| Loss | Fixed per application: cross-entropy for modular, MSE for MNIST and teacher–student |
| Optimizers | AdamW (decoupled weight decay), Adam + L2 (coupled), SGD + momentum 0.9 + L2, plain SGD + L2 |
| Information a metric may use | Training data, weights, recorded training telemetry, hyperparameters (γ, lr, …). **Never test data.** |
| Metric computation | Entirely **offline** from stored run data plus deterministic replay, with causality enforced in code |
| Calibration split | Held-out seeds within each application |
| Storage model | **Dense summaries + sparse keyframes + deterministic replay.** Weights at any step are regenerated by restoring the nearest earlier keyframe and training forward. No dense checkpoint store. |
| Reproducibility | **Every run must be deterministically reproducible.** The target is a bit-exact hash match. At minimum, replay must agree with the recorded run within the tolerances in §4.1. A run that fails this check is not usable. |
| Storage location | Molab files do not persist. Each finished run goes to a **public Hugging Face dataset repo**. |
| Compute | Molab Blackwell GPU (96 GB) for sweeps; local RTX 4060 (8 GB) for development and smoke tests |
| Code | Written from scratch in this directory. Nothing is imported from `agop_alignment_testing/`. |

## 4. What each run records

Everything a metric could need is stored, so new metrics never require retraining.
Details are in DESIGN.md §5.

| Stream | Cadence | Contents | Visible to metrics? |
|---|---|---|---|
| **Telemetry** | every `k_log` steps (default 50) | Train loss and accuracy. Per-layer weight norm, gradient norm (data term and regularizer term separately), update norm. The radial and tangential parts of each update. The cosine between gradient and weights. | yes |
| **Train predictions** | every `k_log` steps | argmax predictions on the training set (int16). Teacher–student stores the per-sample error instead. | yes |
| **Dense summaries** | every `k_sum` steps (default 500) | Per-layer singular values. Per-layer W_lᵀW_l for layers with width ≤ 512. Gradient-noise statistics on fixed minibatches. Training-set activation spectra per layer. | yes |
| **Weight fingerprints** | every `k_log` steps | Per layer: sum, sum of squares, and projections onto 8 fixed random vectors. Lets replay be checked at **any** log step, not just at keyframes. | no: replay verification only |
| **Keyframes** | every `k_key` steps (default 10k, ~11 per run including step 0 and the final step) | **Complete training state**: weights, optimizer state (Adam moments / momentum buffers), and RNG states (torch CPU/CUDA, numpy, minibatch-order stream). Stored in fp32. | via replay only |
| **Oracle** | every `k_log` steps | Test loss and accuracy | **no**: scoring only |
| **Metadata** | once | Full config, seeds, code git hash, package versions, torch/CUDA/cuDNN versions, GPU model, determinism flags, wall time, status | config only |

Anything not in the dense streams is obtained by **replay**. To get the weights at step t:
restore the last keyframe at or before t, then run the identical training loop forward
to t. Replay only ever uses the past, so it does not weaken causality.

Per-example gradients, minibatch gradient disparity, activation statistics and AGOPs at
arbitrary steps are computed during replay. One replay pass per run feeds **all**
signals that need weights, so the extra cost is about one training run per run, at any
time resolution we choose.

### 4.1 Deterministic reproducibility (hard requirement)

Every run must be reproducible from its config, seed and code version. Replay is only
trusted if it reproduces the recorded run.

**Determinism setup** (fixed in code, recorded in metadata):
- `torch.use_deterministic_algorithms(True)`, `CUBLAS_WORKSPACE_CONFIG=:4096:8`,
  cuDNN benchmark off, TF32 off for matmul and cuDNN.
- All randomness drawn from named seed streams (data split, teacher, init, minibatch
  order). There is no global RNG use anywhere in the training loop.
- Replay runs on the **same GPU model and the same pinned software stack** as the
  original run. Metadata records these, and replay refuses a mismatched environment
  unless overridden.

**Verification levels:**

| Level | Check | Pass condition |
|---|---|---|
| **L0: exact** (target) | SHA-256 of every tensor in the keyframe reached by replay vs. the stored keyframe; telemetry rows replayed vs. stored | Bit-identical |
| **L1: tolerance** (minimum acceptable) | Per layer, at every keyframe: ‖w_replay − w_stored‖ / ‖w_stored‖. At every log step: fingerprints and telemetry, relative difference. Train predictions. | weights ≤ 1e-6 relative; fingerprints and telemetry ≤ 1e-5 relative; train-prediction agreement ≥ 99.9% |
| **L2: decision** (sanity) | Every stopping rule's τ computed from replayed signals vs. from dense recorded signals, on the debug set | identical τ |

- Every run carries a `replay_level` field: `L0`, `L1` or `failed`.
- **Runs that are `failed` are excluded from the corpus** and rerun.
- Replay drift accumulates with distance from a keyframe. The tolerances apply to the
  worst case: the step just before the next keyframe.
- The tolerances are starting values. Phase 1 measures actual drift and fixes them.

### Storage estimate

All values are fp32 and use the full model sizes and full grid.

| Variant | Params | Keyframes (~11 × weights + optimizer state) | Dense streams | Runs | Total |
|---|---|---|---|---|---|
| teacher–student | 11k | ~1.5 MB | <5 MB | 432 | ~3 GB |
| modular (all ops) | 0.41M | ~55 MB | ~20 MB | 624 | ~47 GB |
| MNIST depth 3 | 0.2M | ~27 MB | ~15 MB | 96 | ~4 GB |
| MNIST depth 8 | 1.3M | ~170 MB | ~40 MB | 96 | ~20 GB |
| **Total** | | | | | **≈ 75 GB** |

The previous design needed ≈ 470 GB. This one fits with no compromise on model size,
breadth or precision. If needed, `k_key` can be raised to 20k, which halves keyframe
storage at the cost of longer replays.

## 5. Metrics to evaluate

Each metric produces a **signal**: a time series computed causally from stored data. A
shared **rule template** turns a signal into a stopping step: causal smoothing, then a
threshold (with direction), then a patience window. The rule's hyperparameters are
calibrated on seeds {0, 1} and scored on seed {2}.

### Candidates

| ID | Family | Signal |
|---|---|---|
| S1 | Regularized-objective stationarity | ‖∇L_data + γw‖ / ‖γw‖ (coupled optimizers). For AdamW, ‖Δw‖ / (lr·γ·‖w‖). Also the rate of change of log‖w‖ relative to −lr·γ. All per layer and aggregated. |
| S1b | Same family | Mahsereci's evidence-based criterion with the weight-decay term added (gradient SNR computed from per-example gradients) |
| S1c | Same family | S1 with the logit-scaling direction projected out, to survive softmax collapse (cross-entropy runs) |
| N1 | Weight norm | ‖w‖ per layer and its log-derivative |
| R1 | Rank / spectrum | Effective rank, participation ratio and spectral entropy of each layer's activation covariance on the training set |
| R2 | Same family | The same three spectral measures on each weight matrix |
| F1 | Feature stationarity | ‖ΔNFM_l‖ / ‖NFM_l‖ between consecutive evaluation steps, where NFM_l = W_lᵀW_l |
| F2 | Same family | Increment and consecutive alignment of the input AGOP, (1/n)Σ JJᵀ |
| F3 | Same family | Linear CKA between consecutive training-set feature snapshots, per layer |

### Baselines

| ID | Baseline | Note |
|---|---|---|
| B0 | Fixed budget | Stop at step T_fixed |
| B1 | Training-loss patience | Expected to stop on the plateau |
| B2 | Mahsereci et al. 2017 evidence-based criterion | No weight-decay term. Expected to stop on the plateau. |
| B3 | Gradient disparity (Forouzesh & Thiran 2021) | |
| B4 | Label Wave (Yuan et al. 2024) | Expected to stop on the plateau |
| B5 | HTSR α and correlation traps (Prakash & Martin 2025/26) | Main competitor |
| B6 | Validation-loss patience | **Oracle reference**: uses held-out data, so it is reported separately and never counted as a contender |

### Scoring

Computed per run, then aggregated per application and overall.

- **Regret** (main score): `max_acc − acc(τ)`
- **ε-pass**: `acc(τ) ≥ max_acc − ε`, with ε = 0.01
- **Lag**: `τ − t_ε`, where `t_ε` is the first step with `acc ≥ max_acc − ε`
- **Premature-stop rate**: fraction of runs with `τ < t_ε`
- **Never-stopped rate**: fraction of runs with no stop inside the horizon
- **Seed variance**: of each of the above

## 6. Phases and gates

Each phase ends at a gate. We don't start the next phase until the gate passes.

### Phase 0: scaffold and infrastructure
- Package skeleton, config system, run store (writer and reader), Hugging Face sync, CLI
  entry points, test harness.
- **G0:** A dummy 200-step run completes the full cycle: written, uploaded to a test HF
  repo, deleted locally, downloaded, and read back with checksums matching. A replay
  from its step-0 keyframe reproduces its final keyframe at L0 (bit-exact) on CPU.
  `pytest` passes.

### Phase 1: data, models, training loop (local 4060)
- Three task modules, the MLP with init scale α, four optimizers, the trainer, the
  keyframe schedule, all recording streams, and the **replay engine** (§4.1).
- **G1 (reproductions):** Each must show grokking qualitatively, with plots committed:
  - Omnigrok Fig. 2b: teacher–student with α = 2, small γ → grokking; γ = 0 → no
    generalization; α = 0.5 → fast.
  - Omnigrok Fig. 3d: MNIST, 1k samples, large α, AdamW → grokking.
  - Modular `x+y`, AdamW, γ = 1, fraction 0.3–0.5 → grokking.
  - Deep Grokking: MNIST depth 8 shows a two-stage rise for at least one setting. This
    is a soft gate. If it doesn't appear, we note it and continue.
- **G1-det (replay determinism, hard gate):** For one config per application × every
  optimizer:
  - Two independent trainings with the same config and seed give identical keyframe
    hashes (L0) on the same device. Checked on both CPU and the 4060.
  - Replay from every keyframe k reproduces keyframe k+1 at L0, or at least L1.
    Fingerprints match at every log step in between.
  - Measure the worst-case drift where L0 fails, and freeze the L1 tolerances in
    `configs/replay_tolerance.yaml`.

  If L1 can't be met for some optimizer or task on the GPU, the fallback is: shorten
  `k_key` for that case and re-measure. If it still fails, train that case on CPU.

### Phase 2: pilot sweep (Molab, small)
- About 60 runs: one seed, every optimizer × γ level × application variant at the middle
  α and middle size.
- Fix `c_app`, the lr per optimizer, `k_log`, `k_sum`, `k_key` and the horizon.
  Measure real wall time, storage and replay throughput.
- Repeat G1-det **on the Molab Blackwell GPU**, which is where the corpus is trained and
  replayed. Record the exact environment (driver, CUDA, torch) to pin for the rest of
  the project.
- **G2:**
  - Grok times are spread over at least 1.5 decades across the γ levels.
  - Every application has at least some never-generalizing runs.
  - The projected corpus is ≤ 100 GB and ≤ the available GPU-hours, counting training
    plus one replay pass per run.
  - Every pilot run verifies at `replay_level ∈ {L0, L1}`.
  - The final grid is frozen in `configs/sweeps/*.yaml`.

### Phase 3: full sweep (Molab)
- Launch in batches by application. Each run uploads to Hugging Face when it finishes.
  A manifest tracks status, so an interrupted session resumes by skipping completed runs.
- **G3:** The manifest shows every run `complete`. A random 5% of runs are
  re-downloaded, pass integrity checks, and are **fully replayed** end to end at L0 or L1.
  Every other run gets a cheap replay check: one randomly chosen keyframe interval.
  Any run at `failed` is retrained. The corpus summary is generated: max accuracy
  per run, t_ε, and a category for each run (grokker, fast, never generalizes,
  multi-stage, late collapse).

### Phase 4: signals
- Implement every signal (S, N, R, F, B families) against the causal stream API. Signals
  that need weights at arbitrary steps get them from the replay-backed stream: one replay
  pass per run feeds all such signals together. During that pass, replay is checked
  against the stored fingerprints at every log step, and the pass aborts on any
  out-of-tolerance step.
- **Causality test (required for every signal):** Perturb all stored data after step t.
  The signal values at steps ≤ t must not change.
- Compute signals for the whole corpus. Cache them as Parquet, one file per
  (signal, run). Upload the cache to HF as well.
- **G4:** All causality tests pass. The signal cache is complete. Diagnostic plots exist
  for each signal on a fixed debug set of runs.

### Phase 5: rules, calibration, evaluation
- Grid-search each rule's hyperparameters on seeds {0, 1}, minimizing mean regret. Ties
  are broken by lag.
- Calibrate two ways: per application, and one global setting across all applications.
  The second tests whether a rule transfers.
- Score on seed {2}. Produce the results tables and plots.
- **G5:** A reproducible `evaluate` command regenerates every table from the HF data
  from scratch.

### Phase 6: analysis and write-up
- Failure analysis by run category: which rules stop on the plateau, which miss the
  second stage, which are fooled by slingshot or softmax collapse.
- Ablations: per-layer vs. aggregated signals; smoothing; dependence on evaluation
  resolution (cheap to vary now, since replay gives any step).

## 7. Compute plan (rough; the pilot replaces these numbers)

- The models are small. On the Blackwell GPU, run **8–24 training processes
  concurrently**, each a single run. That's simpler than vectorizing runs together, and
  enough to keep the GPU busy at these sizes.
- Rough per-run wall time at 1e5 steps:
  - teacher–student: a few minutes
  - modular: ~10 min
  - MNIST depth 8: ~20–30 min
- About 1,250 runs at 16-way concurrency is **≈ 15–25 Molab hours**, split across
  sessions.
- Phase 4 (signals) runs on the **same GPU type** as training, because replay
  determinism depends on it. Cost per run ≈ one training run (the replay) plus the
  signal math (per-example gradients and AGOPs dominate). Budget about another 15–25
  Molab hours. Runs are processed in a streaming loop: download the keyframes, replay
  and compute, upload the signal cache, delete the local copy.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Molab session ends mid-batch | Runs are short. The manifest plus per-run upload means we lose at most the runs in flight. |
| Hugging Face commit rate limits / file counts | Upload in batched commits (about 10 runs per commit). Keyframes go in one file per run, so there are ~6 files per run and ~8k in total. |
| Replay is not reproducible (GPU nondeterminism, library or driver updates) | Determinism flags in code; pinned environment recorded per run; L0/L1 verification on every replay; hard gates G1-det and G2. The keyframe interval bounds how far drift can spread. As a last resort, train and replay on CPU. |
| Molab's environment changes between sessions | Pin package versions. Record the driver, CUDA and GPU model per run. Replay refuses a mismatched environment unless explicitly overridden, and even then it must still pass L1. |
| Some combinations never grok within the horizon | Expected. They form the never-generalizes category, and the pilot ensures there are enough grokkers too. |
| 3 seeds gives only 1 held-out seed | See Q1 |
| Softmax collapse / NaNs in cross-entropy runs | Recorded as a run outcome, not a failure. Training stops on NaN, and `status=diverged` is stored. Diverged runs are scored separately. |

  suggest 4 seeds: {0, 1} for calibration and {2, 3} held out. That costs +33%
  compute and storage. Decision needed before G2.
- **Q2. Molab session limits.** What is the maximum session length? Can a session keep
  running in the background? This sets the batch size in Phase 3.
- **Q3. Hugging Face.** Which account or organization hosts the dataset repo, and under
