# Test-free stopping: design document

This document describes the code flow, modules, classes, storage format and causality
guarantees. [PLAN.md](PLAN.md) covers what is run and in what order. Signatures below
are interface sketches, not final code.

---

## 1. Design principles

1. **Train once, measure forever.** A training run records raw data only: dense small
   summaries plus sparse **keyframes** of the complete training state. Every metric is
   computed later, offline. Anything not stored densely, such as the weights at an
   arbitrary step, is regenerated by **deterministic replay** from the nearest earlier
   keyframe. Adding a metric never requires a new training run.
2. **Causality is structural, not a matter of discipline.** Signals receive data as a
   time-ordered stream and never get a handle to the whole run. Every signal must also
   pass an automated test that perturbs the future (§7.4).
3. **The test set is quarantined.** Test-side data lives in a separate stream and a
   separate type (`OracleRecord`), which only the evaluation package may read. Nothing
   in `signals/` or `rules/` can import it (§10).
4. **Three independent layers, each with a single interface:**
   - task (what is learned)
   - training (how)
   - measurement (signals → rules → scores)

   A new dataset, optimizer, signal or rule is one file plus a registry entry.
5. **Every run is deterministically reproducible. This is a hard requirement.**
   - Data is regenerated from the seed, so it is never stored.
   - Training is bit-exact on a fixed environment.
   - Replay is verified against stored hashes and fingerprints. The target is a bit-exact
     match (L0). The minimum is agreement within fixed numerical tolerances (L1). A run
     that meets neither is excluded (§6.5).
   - Each run records the code git hash, package versions, CUDA/cuDNN/driver, GPU model
     and determinism flags.

## 3. End-to-end flow

```
 sweep YAML ──grid.expand──▶ [RunConfig]  ──launcher──▶  Trainer(RunConfig)
                                                     │  writes via RunWriter
                                                     ▼
                                   runs/<app>/<run_id>/  ──hub.upload──▶ HF dataset repo
                                                                            │
          ┌─────────────────────── hub.download ◀───────────────────────────┘
          ▼
   RunReader ─┬────────────────────────────────▶ CausalStream (time-ordered Observations,
              └─ keyframes ─▶ ReplayEngine ──────▶   weights at any step, no test data)
                              (verifies vs. fingerprints; aborts on drift)
                     │
                     ▼
            Signal.update(obs) ...   ──▶ signal cache  cache/<signal>/<run_id>.parquet
                                                     │
          RunReader ──▶ Oracle (test acc) ──▶ GroundTruth(max_acc, t_eps, category)
                                                     │
                        StoppingRule(signal series) ─┴─▶ τ  ──▶ Scoring ──▶ Report
                                         ▲
                       Calibration (seeds 0,1) tunes rule params; scored on held-out seeds
```

The pipeline has four stages. Each stage reads only the previous stage's stored output,
so each can be rerun on its own:

1. **train**: config → run data (dense streams + keyframes)
2. **signals**: run data + replay → signal cache
3. **calibrate**: signal cache + oracle (calibration seeds) → rule parameters
4. **evaluate**: signal cache + rule parameters + oracle (held-out seeds) → tables

## 4. Configs and identity

```python
@dataclass(frozen=True)
class TaskConfig:      name: str; params: dict            # e.g. {"op": "x+y", "p": 97, "train_frac": 0.3}
@dataclass(frozen=True)
class ModelConfig:     depth: int; width: int; activation: str; init_scale: float
@dataclass(frozen=True)
class OptimConfig:     name: str; lr: float; weight_decay: float; momentum: float = 0.0; betas: tuple = (0.9, 0.98)
@dataclass(frozen=True)
class RecordConfig:    log_every: int = 50; summary_every: int = 500; keyframe_every: int = 10_000
                       n_fingerprint_proj: int = 8
@dataclass(frozen=True)
class RunConfig:
    task: TaskConfig; model: ModelConfig; optim: OptimConfig; record: RecordConfig
    loss: str; batch_size: int | None; steps: int; seed: int
    @property
    def run_id(self) -> str: ...   # "<app>__<readable-axes>__<8-char hash of canonical JSON>"
    @property
    def group_id(self) -> str: ... # run_id with the seed removed; used for the seed split
```

- `run_id` is deterministic. Rerunning a sweep YAML regenerates the same IDs, which is
  what makes resuming work.
- **Seed handling** (`tfs/seeding.py`). One integer seed is split by
  `numpy.random.SeedSequence` into independent named streams: data, teacher, init,
  order, probe, fingerprint. Changing one never shifts the others.
- **Minibatch order is stateless.** The batch at step t is a pure function of
  (order seed, t): each epoch's permutation is derived from (order seed, epoch). Nothing
  else in a training step is random. A keyframe therefore needs no RNG state, and replay
  cannot drift through RNG bookkeeping.

## 5. Run storage format

One directory per run, identical locally and on Hugging Face:

```
runs/<app>/<run_id>/
  meta.json            # RunConfig, status, environment, code version, versions, wall time, param shapes
  telemetry.parquet    # one row per log step (train side only)
  train_preds.npy      # int16 [n_log, n_train]  (teacher-student: float16 per-sample error)
  summaries.safetensors   # dense summaries, keys "s{step}/<name>/l{i}"
  fingerprints.parquet # one row per log step: per-layer sum, sumsq, 8 random projections
  keyframes.safetensors   # ~11 keyframes: full TrainState, keys "k{step}/..."
  keyframe_hashes.json # step -> {tensor key: sha256}
  oracle.parquet       # test loss/acc per log step  (QUARANTINED: see §10)
  checksums.json       # sha256 of every file above (immutable after training)
  DONE                 # written last; presence = run complete
  replay_report.json   # latest replay verification (mutable, outside checksums.json)
```

The run's replay level lives in `replay_report.json` and in the manifest, never in
`meta.json`. That keeps every checksummed file immutable after training, so a
re-verification never invalidates the checksums.

### `telemetry.parquet` columns

| Column | Meaning |
|---|---|
| `step` | |
| `train_loss`, `train_acc` | |
| `l{i}_w_norm`, `l{i}_g_norm` | per layer; `g` is the data-loss gradient |
| `l{i}_reg_g_norm` | gradient of the coupled L2 term (0 for AdamW) |
| `l{i}_update_norm` | ‖Δw‖ for the step actually taken |
| `l{i}_update_radial`, `l{i}_update_tangential` | Δw split along and across w |
| `l{i}_cos_g_w` | cosine between gradient and weights |
| `lr`, `nan_flag` | |

Totals over layers are derived on read, not stored.

### Dense summaries (`summaries.safetensors`)

Recorded every `summary_every` steps. These are the weight-derived quantities that the
cheap signals need at high time resolution without replay:
- per-layer singular values of W_l
- per-layer W_lᵀW_l, only for layers whose input width is ≤ 512
- per-layer singular values of the training-set activation covariance
- gradient-noise statistics (per-layer mean and variance of minibatch gradients over a
  fixed set of `n_probe` minibatches, drawn from a dedicated RNG stream)

Signals that need anything beyond this go through replay.

### Weight fingerprints (`fingerprints.parquet`)

Recorded every log step. Per layer:
- Σw and Σw², in float64
- ⟨w, r_j⟩ for j = 1..8, where the r_j are fixed random unit vectors (from their own seed
  stream, so they are regenerable)

These are cheap and fit in a few MB. They let replay be checked at **every log step**,
not just at keyframes. They are never exposed to signals.

### Keyframes (`keyframes.safetensors`)

A keyframe is the complete `TrainState` at a step:

```python
@dataclass
class TrainState:
    step: int
    weights: list[Tensor]                 # fp32, MLP.weight_list() order (+ biases)
    optim_state: dict[str, Tensor]        # flattened optimizer.state_dict() tensors (Adam m, v, step; momentum buffers)
    # no RNG state: minibatch order is a pure function of the step (§4)
    def to_flat(self) -> dict[str, Tensor]: ...
    @classmethod
    def from_flat(cls, step: int, d: dict[str, Tensor]) -> "TrainState": ...
```

- Keyframes are taken at step 0, every `keyframe_every` steps, and at the final step.
  The horizon is always a keyframe.
- Always fp32. Keyframes are small in number, and replay must restart from exact state.
- `keyframe_hashes.json` holds a SHA-256 per tensor. It is used by L0 verification and
  by upload integrity checks.

### Schedules

`training/schedule.py` defines `log_steps`, `summary_steps` and `keyframe_steps` as
nested sets: every keyframe step is a summary step, and every summary step is a log
step. So telemetry, predictions, fingerprints and oracle rows exist at every keyframe
and every summary step.

### Writer and reader

```python
class RunWriter:                       # used only by Trainer
    def __init__(self, run_dir: Path, cfg: RunConfig, layer_shapes: list): ...
    def log(self, step, telemetry: dict, train_preds: np.ndarray, fingerprint: dict, oracle: dict): ...
    def summary(self, step, summaries: dict[str, np.ndarray]): ...
    def keyframe(self, state: TrainState): ...        # buffered; written with hashes
    def finalize(self, status: str, env: EnvRecord): ...   # flush, meta.json, DONE

class RunReader:                       # lazy, read-only
    def __init__(self, run_dir: Path): ...
    config: RunConfig; status: str; env: EnvRecord
    log_steps: np.ndarray; summary_steps: np.ndarray; keyframe_steps: np.ndarray
    def telemetry(self) -> pd.DataFrame: ...
    def train_preds(self) -> np.ndarray: ...
    def summaries(self, step: int) -> dict[str, np.ndarray]: ...
    def keyframe(self, step: int) -> TrainState: ...
    def fingerprints(self) -> pd.DataFrame: ...       # used by ReplayEngine only
    # NOTE: no oracle accessor here. See evaluation/oracle.py.
```

### `hub.py` and `manifest.py`

- **Manifest.** A table with one row per `run_id`: status (planned, running, complete,
  diverged, failed), size, upload commit and checksum. It is stored in the HF repo root
  and is the source of truth for resuming.
- **Upload.** Runs are grouped into batched commits through
  `huggingface_hub.HfApi.create_commit` (about 10 runs per commit) to stay under rate
  limits. A local run directory is deleted only after the upload is confirmed and the
  checksums match.
- **Download.** `hub.fetch(run_id, parts=...)` downloads only the parts needed. For
  example, signals that use telemetry alone skip the keyframes.
- **File count.** About 9 files per run, roughly 11k across the corpus. That is well
  within Hugging Face's comfortable range.
- **Authentication.** The token comes from the `HF_TOKEN` environment variable only. It
  is never written to config or logs.

## 6. Training layer

### Tasks

```python
@dataclass
class TaskData:
    x_train: Tensor; y_train: Tensor; x_test: Tensor; y_test: Tensor
    n_classes: int | None     # None for regression

class Task(Protocol):
    name: str
    def build(self, cfg: TaskConfig, rng: np.random.Generator) -> TaskData: ...
    def accuracy(self, pred: Tensor, y: Tensor) -> Tensor: ...    # argmax or threshold-θ
    def train_pred_record(self, pred: Tensor, y: Tensor) -> np.ndarray: ...
```

- **Modular.** Builds every (a, b) pair and splits them at `train_frac`.
- **MNIST.** Loads from a cached torchvision download (checksummed), then takes a seeded
  subset of the training set. The test set is the full 10k images.
- **Teacher–student.** Builds the teacher from its own seed stream, then draws
  `N_train` and `N_test` Gaussian inputs.

### Model

```python
class MLP(nn.Module):
    def __init__(self, d_in, d_out, depth, width, activation, init_scale): ...
    # PyTorch default init, then every weight multiplied by init_scale (Omnigrok's α).
    def forward(self, x) -> Tensor: ...
    def features(self, x) -> list[Tensor]: ...     # post-activation output of every hidden layer
    def weight_list(self) -> list[Tensor]: ...     # fixed layer order, used everywhere
```

Biases are included, using the default PyTorch MLP convention. `features()` is used
offline by the spectral and feature signals.

### Optimizers

`optim.factory.build(cfg, model)` returns a `torch.optim` optimizer plus a `RegSpec`
describing how weight decay enters:

| name | torch optimizer | weight decay |
|---|---|---|
| adamw | AdamW | decoupled (`weight_decay=γ`) |
| adam_l2 | Adam | coupled: `γ/2 ‖w‖²` added to the loss |
| sgd_momentum | SGD(momentum=0.9) | coupled |
| sgd | SGD | coupled |

`RegSpec` is stored in `meta.json`. Signals read it to form the correct stationarity
quantity for each optimizer.

### Trainer

```python
class Trainer:
    def __init__(self, cfg: RunConfig, writer: RunWriter, device: str): ...
    def run(self) -> str:                    # returns final status
        # for step in 0..steps:
        #   if step in keyframe_steps: writer.keyframe(TrainState.capture(...))
        #   if step in log_steps:      eval train (and test -> oracle), telemetry, fingerprint, writer.log(...)
        #   if step in summary_steps:  writer.summary(step, summaries.compute(...))
        #   take one optimizer step (record Δw for update telemetry)
        #   on non-finite loss: writer.finalize("diverged"); return
    def advance(self, state: TrainState, to_step: int, on_step=None) -> TrainState: ...
        # the single training-step implementation, shared by run() and ReplayEngine
```

- Telemetry is computed in `training/telemetry.py` from the gradient and Δw of the step
  just taken.
- Train and test evaluations both run in `torch.no_grad()`. The test evaluation writes
  only to the oracle stream.
- **One code path.** `run()` and replay both call `advance()`, so replay cannot drift
  from training through duplicated logic.
- **Recording is side-effect-free.** Evaluation, telemetry, summaries and fingerprints
  run under `torch.no_grad()`, never touch the training RNG streams, and draw any
  randomness of their own (e.g. probe minibatches) from dedicated streams. Recording at
  a different cadence therefore never changes the training trajectory. This is what lets
  replay skip recording entirely.

### Launcher

```python
def launch(configs: list[RunConfig], workers: int, device: str, upload: bool): ...
```

- One process per run, up to `workers` concurrent processes.
- Runs already marked `complete` in the manifest are skipped.
- A finished run is handed to the upload queue.
- A failed run records its traceback in `meta.json` with `status=failed`, and the batch
  carries on.

### 6.5 Determinism and replay

**Determinism setup** (`training/determinism.py`, applied once at process start):
- `torch.use_deterministic_algorithms(True)` and `CUBLAS_WORKSPACE_CONFIG=:4096:8`
- `torch.backends.cudnn.benchmark = False`
- TF32 disabled: `torch.backends.cuda.matmul.allow_tf32 = False`,
  `torch.backends.cudnn.allow_tf32 = False`
- full-batch losses use a fixed reduction order. No atomics-based ops (e.g. `index_add`
  on CUDA) are used in the training step.
- `EnvRecord` captures torch, CUDA, cuDNN, driver, GPU name, Python and numpy versions,
  and the flags above. It is stored in `meta.json`.

```python
@dataclass(frozen=True)
class EnvRecord:
    torch: str; cuda: str | None; cudnn: str | None; driver: str | None
    gpu: str | None; python: str; numpy: str; flags: dict
    def compatible_with(self, other: "EnvRecord") -> bool: ...   # same GPU model + same versions

class ReplayEngine:
    def __init__(self, reader: RunReader, ctx: TrainContext, tolerance: ReplayTolerance,
                 allow_env_mismatch: bool = False): ...
    def iterate(self, steps: Iterable[int]) -> Iterator[tuple[int, MLP]]:
        # steps must be increasing. Restores the latest keyframe <= first step, then
        # advances, yielding the model at each requested step. At every log step passed
        # through, compares fingerprints (and telemetry) to the stored values. At every
        # keyframe passed through, compares the full state. Raises ReplayDivergence when
        # out of tolerance. It never reads beyond the largest requested step.
    def verify(self, intervals: list[tuple[int, int]] | Literal["all"]) -> ReplayReport: ...

@dataclass(frozen=True)
class ReplayTolerance:                      # loaded from configs/replay_tolerance.yaml
    weight_rel: float = 1e-6                # per layer, ||w_replay - w_stored|| / ||w_stored||, at keyframes
    optim_rel: float = 1e-5                 # per optimizer-state tensor, at keyframes
    fingerprint_rel: float = 1e-5           # per fingerprint entry, at every log step
    telemetry_rel: float = 1e-5             # per telemetry column, at every log step
    pred_agreement: float = 0.999           # train-prediction agreement, at every log step
```

**Verification levels.** Recorded per run in `replay_report.json` and the manifest (`replay_level`).

| Level | Condition |
|---|---|
| **L0 (target)** | Every keyframe reached by replay is bit-identical, by SHA-256 per tensor. Telemetry and fingerprints are bit-identical. |
| **L1 (minimum acceptable)** | Every check is within `ReplayTolerance`. The worst observed relative error is recorded per run. |
| **failed** | Any check is out of tolerance. The run is excluded from the corpus and retrained. |

The tolerances above are starting values. Phase 1 (G1-det) measures the actual drift
and freezes them.

**Integrity before replay.** `ReplayEngine` first checks every present file against
`checksums.json` and raises `CorruptRun` on a mismatch. Replay compares against the
stored keyframes and streams, so they must be the recorded bytes.

**When verification happens:**
1. **After training, on Molab:** replay one random keyframe interval and set the
   preliminary `replay_level`.
2. **G3 audit:** full replay of a random 5% of runs.
3. **During every signal pass:** `ReplayEngine.iterate` checks continuously. A pass that
   raises is discarded, and the run is flagged.

**Environment.** Replay refuses to run when `EnvRecord.compatible_with` is false. It can
be overridden with `allow_env_mismatch=True`, but the run must still pass L1.
Practically, this means the corpus is trained and replayed on the same Molab GPU type
with a pinned environment.

**Where drift can come from**, and how it is handled:
- GPU kernel nondeterminism: prevented by the flags above.
- Library or driver updates: prevented by pinning, and detected by `EnvRecord`.
- Floating-point reassociation across devices: avoided by never replaying across device
  types.
- Drift is bounded by `keyframe_every`, since each interval restarts from exact stored
  state.

## 7. Measurement layer

### 7.1 Causal stream

This is the only way signal code can see run data.

```python
@dataclass(frozen=True)
class Observation:
    step: int
    telemetry: Mapping[str, float]          # this log step's row only
    train_preds: np.ndarray                 # this log step only
    summaries: Mapping[str, np.ndarray] | None   # present only at summary steps
    model: MLP | None                       # present only at "eval" steps; produced by ReplayEngine

class TrainContext:                          # static, time-independent, train-side only
    config: RunConfig; reg: RegSpec
    x_train: Tensor; y_train: Tensor         # regenerated from the seed; NO test tensors
    # (models are supplied by the stream via replay, not built by signals)

class CausalStream:
    def __init__(self, reader: RunReader, cadence: Literal["log", "summary", "eval"],
                 eval_steps: Sequence[int] | None = None, replay: ReplayEngine | None = None): ...
    # "log"/"summary": stored data only, no replay.
    # "eval": also yields a replayed model at each eval step. The default eval grid is
    #         the union of 200 log-spaced and 400 uniform steps; any grid is possible.
    def __iter__(self) -> Iterator[Observation]: ...   # strictly increasing step order
    context: TrainContext
```

`CausalStream` never yields the oracle and never exposes the reader or the replay
engine. History has to be kept inside the signal's own state, so access to the future is
impossible by construction. Replay also only ever moves forward, so producing the model
at step t never needs anything stored after t.

**Shared replay pass.** `compute_signals.py` groups every signal with `cadence="eval"` on
the same eval grid and drives them from **one** stream. Each run is replayed once per
signal pass, not once per signal.

### 7.2 Signals

```python
class Signal(ABC):
    name: str
    cadence: Literal["log", "summary", "eval"]   # which steps it emits on
    requires: set[str]                        # {"telemetry", "preds", "summaries", "replay"} -> drives download + replay
    def __init__(self, ctx: TrainContext, **params): ...
    @abstractmethod
    def update(self, obs: Observation) -> dict[str, float] | None: ...
    #   returns {"value": ..., optional per-layer keys}, or None until defined

@register_signal("s1_reg_stationarity")
class RegStationarity(Signal): ...
```

`compute_signals.py` drives the process: for each run and each signal, iterate the
stream, collect the non-None outputs, and write `cache/<signal>/<run_id>.parquet` with
columns `step`, `value` and the per-layer columns.

Signal families and what each one needs:

| Family | Cadence | Needs | Expensive part |
|---|---|---|---|
| S1 | log | telemetry | none |
| S1c | eval | replay | projecting out the logit-scaling direction |
| S1b, B2 | eval | replay + training data | per-example gradients at each eval step (`torch.func.vmap(grad)`) |
| N1 | log | telemetry | none |
| R1 (cheap) | summary | summaries (activation spectra) | none |
| R1 (dense), F3 | eval | replay + training data | one forward pass on the training set per eval step |
| R2, B5 | summary | summaries (singular values) | power-law fit only |
| F1 | summary | summaries (W_lᵀW_l), or eval via replay for wide layers | none |
| F2 | eval | replay + training data | input Jacobians: n × d_out backward passes, batched |
| B1 | log | telemetry | none |
| B3 | eval | replay + training data | two minibatch gradients per eval step, from a fixed RNG stream |
| B4 | log | preds | none |

Shared math lives in `signals/_linalg.py` and has its own unit tests against brute-force
references: effective rank, participation ratio, spectral entropy, linear CKA,
power-law α fit, per-example gradients, input AGOP.

### 7.3 Rules

```python
@dataclass(frozen=True)
class RuleSpec:
    signal: str; column: str = "value"
    smoother: str = "ema"; smooth_param: float = 0.1
    direction: Literal["below", "above"]; threshold: float
    patience: int                      # consecutive emitting steps the condition must hold
    min_step: int = 0

class StoppingRule:
    def __init__(self, spec: RuleSpec): ...
    def stop_step(self, series: pd.DataFrame) -> int | None:
        # iterate rows in step order; causal smoothing; return the first step at which
        # the condition has held for `patience` consecutive rows; None if never.
```

- Rules see only the signal series, which is causal by §7.1, and apply only causal
  smoothing (EMA, trailing median).
- The stopping step τ is always a step at which the signal emitted, so oracle accuracy
  is defined there. Summary and eval steps are always log steps; eval grids are
  restricted to log steps.
- Baselines that are a fixed procedure rather than a threshold, such as B0 and the B6
  oracle, implement the same `stop_step` interface.

### 7.4 Causality enforcement

Two layers of protection:

1. **Structural.** The `CausalStream` / `Signal.update` API described above.
2. **Empirical: `test_causality.py`.** For every registered signal, on a small synthetic
   run:
   1. Compute the signal series A.
   2. Pick a cut step t. Replace every stored item at steps > t with random values of
      the same shape: telemetry, predictions, summaries, fingerprints, and every
      keyframe after t. Replay is run with verification disabled for this test only,
      since the corrupted future would otherwise trip it. Correct replay never reaches
      past t anyway.
   3. Compute series B.
   4. Assert that A and B are identical for steps ≤ t.

   The test is parameterized over all names in the registry, so a new signal is covered
   automatically. The same test also runs on `StoppingRule`.

3. **`test_replay.py`** covers replay itself, on CPU, for every optimizer:
   - train → replay from each keyframe → L0 match
   - replaying with recording on vs. off gives identical trajectories (recording is
     side-effect-free)
   - a deliberately perturbed keyframe raises `ReplayDivergence`
   - replaying to step t never opens a keyframe after t

## 8. Evaluation layer

```python
class Oracle:                                   # evaluation/oracle.py, the only reader of oracle.parquet
    def __init__(self, run_dir: Path): ...
    def test_acc(self) -> pd.Series: ...        # indexed by step

@dataclass
class GroundTruth:
    max_acc: float; argmax_step: int; t_eps: int; category: str
    # category in {grokker, fast, never, multi_stage, late_collapse, diverged}, by fixed rules on train/test curves

def score(tau: int | None, oracle: Oracle, gt: GroundTruth, eps: float) -> dict:
    # regret, eps_pass, lag, premature, never_stopped
    # (tau=None -> stop at horizon end, flagged never_stopped)

class Calibrator:
    def __init__(self, search_space: dict, objective="mean_regret", tiebreak="mean_lag"): ...
    def fit(self, signal: str, runs: list[str]) -> RuleSpec: ...   # runs = calibration seeds only

def evaluate(rule_specs: dict[str, RuleSpec], runs: list[str]) -> pd.DataFrame: ...
```

- **Split.** `seed ∈ {0, 1}` is calibration and `seed ∈ {2}` (or {2, 3}) is held out,
  defined in one place: `evaluation/split.py`. `Calibrator.fit` asserts it never
  receives a held-out run.
- **Calibration modes.**
  - per application: one `RuleSpec` per (signal, application)
  - global: one `RuleSpec` per signal across all applications

  Both are reported.
- **Report outputs** in `results/`:
  - main table: rows are rules, columns are mean/median regret, ε-pass, premature rate,
    lag and never-stopped rate; per application and overall
  - per-category breakdown
  - regret CDFs
  - plots for the debug set: train/test accuracy, the signal, and the rule's τ

## 10. Test-data quarantine

- `oracle.parquet` is read only in `tfs/evaluation/oracle.py`.
- `tests/test_quarantine.py` enforces this statically. It parses every module under
  `tfs/signals`, `tfs/rules`, `tfs/causal` and `tfs/storage/reader.py`, and fails if any
  of them imports `tfs.evaluation` or mentions the `oracle` filename.
- `TrainContext` is built from `Task.build(...)`, but **only the training tensors** are
  kept. The test tensors are dropped before the context object exists.

## 11. Conventions

- Python ≥ 3.11, torch, numpy, pandas/pyarrow, safetensors, huggingface_hub, pyyaml,
  matplotlib, pytest.
- All dependencies are pinned in `pyproject.toml`.
- Layer order is fixed by `MLP.weight_list()`, and every per-layer column uses that
  index.
- Time is always measured in optimizer **steps**, never epochs, across all applications.
- Keyframes are always fp32. Offline math runs in float32 or float64.
- The pinned environment (exact versions) lives in `pyproject.toml` plus
  `configs/env_lock.txt`. Changing either invalidates replay compatibility for runs
  recorded under the old environment.
- Every figure in `results/` is regenerated by a script, never edited by hand.
